# گزارش ممیزی و آزمون MVP Rain

تاریخ ممیزی: ۲۰۲۶-۱۰-۱۶

## جمع‌بندی

هستهٔ MVP با آزمون‌های واحد و API ممیزی شد. **ایرادهای تأییدشدهٔ امنیتی/منطقی اصلاح شدند** و دادهٔ آزمایشی در پایان به baseline بازگردانده شد.

## ماتریس آزمون

|---|---|---:|---|

## اصلاحات انجام‌شده

1. **مرزبندی scope در سرور** تقویت شد؛ پاسخ mutation ذخیره نیز scoped است و full state را به مشاور برنمی‌گرداند.
2. ساخت رکورد جدید در scope مجاز برای مشاور/لیدر امکان‌پذیر شد.
3. تغییر غیرمجاز `sectionId`، `assigneeId` و مالکیت رکوردهای موجود خنثی می‌شود.
4. برای mutation ذخیرهٔ Rain اعتبارسنجی ساختاری حداقلی اضافه شد.
5. مکان خالی دیگر با `includes` به‌صورت خودکار منطبق نمی‌شود.
6. فرم پیگیری نتیجه و اقدام بعدی را جدا می‌گیرد.
7. سابقهٔ پیگیری مرتبط در صفحهٔ مشتری و جزئیات ملک نمایش داده می‌شود.
8. کارت خوشامدگویی Today در موبایل فشرده‌تر شد.
9. تست‌های permission و مکان نامعلوم اضافه شدند.

## مواردی که هنوز نیاز به کار/تصمیم دارند

- **ویرایش کامل مشتری، نیاز و پیگیری در رابط هنوز وجود ندارد**؛ مشتری و نیاز فقط از مسیر ثبت ساخته می‌شوند و پیگیری فقط تکمیل‌شدن دارد. ویرایش ملک موجود وجود دارد. این مورد به‌عنوان gap باقی مانده و در این ممیزی برای جلوگیری از بازطراحی گستردهٔ UI تغییر داده نشد.
- مدل پایگاه‌دادهٔ فعلی یک `rain_states` JSON payload است، نه جدول‌های مستقل برای هر موجودیت. برای MVP رفتار ماندگار و scope آزمون شد، اما برای مقیاس عملیاتی، migration مستقل Office/Section/User/Property/Client/Requirement/MatchReview/FollowUp لازم است.
- اعتبارسنجی mutation در سطح ساختار state است؛ اعتبارسنجی کامل تک‌تک فیلدهای nested و قواعد بازه‌ای بهتر است در مرحلهٔ schema-normalization اضافه شود.
- warning مربوط به `script src="/api/platform/config.js"` در build متعلق به اسکریپت پلتفرم است و build را fail نمی‌کند.
